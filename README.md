# Image Steganalysis for Digital Forensic Examination

This coursework project compares three ways to detect random-position least-significant-bit (LSB) replacement in grayscale images: a five-feature logistic regression classifier, a simplified regular/singular (RS) statistic, and a small convolutional neural network (CNN). The RS score is inspired by RS analysis; it is not the full RS message-length estimator.

## Dataset

Download **BOSSbase 1.01** from the [Binghamton University Digital Data Embedding Laboratory](https://dde.binghamton.edu/download/) (Image Database section). The [direct BOSSbase archive](https://dde.binghamton.edu/download/ImageDB/BOSSbase_1.01.zip) contains the original images. This repository does not include the images or the generated stego files.

`Terminal.py` samples 500 original 512 × 512 grayscale PGM images. For each one, it generates two copies by embedding random bits at randomly selected pixels: one at **0.1 bits per pixel (bpp)** and one at **0.4 bpp**. The stego labels are generated by this code; BOSSbase provides the original images.

## Files

| File | Purpose |
| --- | --- |
| `Terminal.py` | Select images, record SHA-256 hashes, generate and verify stego copies, create source-grouped splits, extract features, train logistic regression, calculate simplified RS scores, and package the data for Colab. |
| `DF (2).ipynb` | Train and evaluate separate small CNNs for the two payload sizes in Google Colab. |

## Run the local pipeline

Install the Python dependencies:

```bash
python3 -m pip install Pillow numpy scikit-learn joblib
```

Extract BOSSbase so that the PGM files are directly inside `BOSSbase_1.01`, for example:

```text
Desktop/
└── BOSSbase_1.01/
    ├── 1.pgm
    ├── 2.pgm
    └── ...
```

From the directory containing `Terminal.py`, run:

```bash
python3 Terminal.py --desktop ~/Desktop --stage all
```

`--desktop` is the parent directory of `BOSSbase_1.01`; change the path if you extracted the dataset elsewhere. Run `--stage all` on a fresh copy: the selection step deliberately stops if `BOSSbase_selected_500` already exists. To run a single stage later, use `--stage STAGE`, where `STAGE` is one of `select`, `hashes`, `generate`, `splits`, `datasets`, `features`, `logistic`, `rs`, or `archive`. A later stage requires the files produced by its earlier stages.

The script creates:

- `BOSSbase_selected_500/`: 500 source images and `source_manifest.csv`.
- `BOSSbase_generated_500/`: stego images in `0p1/` and `0p4/`, manifests, `splits.csv`, feature tables, logistic models, and RS scores.
- `BOSSbase_project_data.zip`: 1,500 images plus the source and stego manifests and split file, ready for Colab.

Image selection uses seed 42. Source identities are divided with seed 123 into **300 training, 100 validation, and 100 test sources**. Every original image and both of its stego copies receive the same split. The embedding seeds are derived from each filename and payload. The script reopens generated files to verify the embedded bits and records SHA-256 hashes.

## Run the CNN notebook in Colab

1. Open `DF (2).ipynb` in Google Colab and select a GPU runtime if available.
2. The first cell, which uploads one PGM image to inspect its size and mode, is optional. In the next upload cell, upload `BOSSbase_project_data.zip` created by `Terminal.py`.
3. Run the remaining cells in order. They extract the ZIP into `/content/boss_project`, load the same source-grouped splits, train one CNN per payload, and print validation and test results.
4. The final cell packages the saved CNN weights and prediction CSVs into `cnn_results.zip` for download. Colab files are temporary, so download that ZIP if you want to keep those outputs.

The notebook's saved 0.1 bpp training cells have irregular printed epoch labels and include a continuation. Read the recorded validation and test outputs as the results of that run; the labels are not a clean continuous epoch history.

## Evaluation and scope

The reported primary metric is test ROC AUC. The code also reports false positives among 100 test originals and stego detections among 100 test stego images for each payload. Logistic regression uses a fixed score threshold of 0.5. The RS and CNN thresholds use the 95th percentile of scores from validation originals, so their threshold-dependent counts are not measured at the same operating point as logistic regression.

| Method | Test AUC at 0.1 bpp | Test AUC at 0.4 bpp |
| --- | ---: | ---: |
| Logistic regression | 0.540 | 0.691 |
| Simplified RS statistic | 0.977 | 0.999 |
| Small CNN | 0.662 | 0.931 |

These results concern this subset of BOSSbase and this particular random-position LSB replacement procedure. A detector's score is an indicator for further examination, not proof that an arbitrary image contains hidden data.
